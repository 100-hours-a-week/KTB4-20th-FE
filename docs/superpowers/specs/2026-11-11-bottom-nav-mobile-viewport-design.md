# 하단 내비게이션 및 모바일 뷰포트 보정 설계

## 의도

프론트엔드에서 커뮤니티 하단 탭만 제거하고, 휴대폰 기종과 브라우저 UI 높이가 달라도 화면 높이와 하단 고정 UI가 자연스럽게 보이도록 공통 레이아웃을 가볍게 보정한다.

## 목표

- 하단 내비게이션을 메인, 포토미션, 오픈 채팅의 3개 항목으로 표시한다.
- `/community` 라우트와 커뮤니티 페이지는 그대로 유지한다.
- 모바일 브라우저 주소창 변화에 대응하도록 남아 있는 정적 `100vh` 사용을 동적 뷰포트 높이로 보정한다.
- 하단 내비게이션과 공통 루트 영역이 기기 안전영역을 존중하게 한다.
- 백엔드, API, 인증 및 데이터 흐름은 변경하지 않는다.

## 비목표 및 금지사항

- 커뮤니티 기능이나 페이지를 삭제하지 않는다.
- 페이지 디자인, 카드 배치, 사용자 흐름을 재설계하지 않는다.
- 백엔드 저장소나 API 규격을 변경하지 않는다.
- 새 패키지를 추가하지 않는다.

## 접근 방식

1. **선택: 공통 기반만 최소 보정** — 하단 항목과 불필요한 아이콘 import를 제거하고, 공통 루트 및 일부 남은 `100vh` 화면에 `100dvh` 폴백을 적용한다. 기존 디자인을 유지하면서 기종별 높이 차이와 안전영역 문제를 줄인다.
2. **검토 후 제외: 페이지별 반응형 재작업** — 모든 화면의 카드, 그리드, 모달을 폭별로 다시 조정한다. 더 세밀하지만 현재 요청인 “살짝 손보기”보다 범위와 회귀 위험이 크다.

## 구현 제약

- 기존 React 19, TypeScript, Vite, CSS 구조를 유지한다.
- 하단 내비게이션의 접근성 레이블과 키보드 포커스 동작을 유지한다.
- `100vh`는 구형 브라우저 폴백으로 먼저 두고, 지원 브라우저에서 뒤의 `100dvh`가 덮어쓰게 한다.
- 안전영역 보정은 기존 페이지별 하단 여백과 중복되지 않도록 공통 루트와 하단 내비게이션 중심으로 제한한다.

## 검증

- 커뮤니티 탭이 렌더링 목록에서 사라지고 나머지 3개 탭이 균등 배치되는지 확인한다.
- `/community` 라우트와 페이지 파일이 유지되는지 확인한다.
- lint, TypeScript 검사, 프로덕션 빌드를 실행한다.
- 가능하면 개발 서버를 여러 모바일 뷰포트 폭/높이로 확인해 가로 스크롤 및 하단 겹침이 없는지 점검한다.
